# Tools

The authoritative tool contract is `schemas/tools.json`, exported from the
running server (§33.1) via `dev-workspace-mcp export-schemas`. This file is
a human-readable index alongside it — per §72, generated by hand rather
than by a script for now (no task in `docs/TODO.md` builds a generator);
if the two disagree, `schemas/tools.json` is right and this file is stale.

Current tool surface (`contract_version` in `schemas/tools.json`):

| Tool | Purpose |
| --- | --- |
| `repository_list` | List configured/discovered repositories (§7). |
| `list_files` | List files/directories under a workspace path (§13). |
| `read_file` | Read a file, by byte/line range if given (§13). |
| `write_file` | Write a file, with optimistic concurrency (§13). |
| `patch_file` | Apply a unified diff to a file (§13). |
| `delete_file` | Delete a file or directory (§13). |
| `search_files` | Search file contents under a workspace path (§13). |
| `workspace_open` | Ensure a workspace's container exists and is running (§8). |
| `workspace_info` | Report a workspace's current state (§25). |
| `server_info` | Server version, capabilities, and health (§25). |
| `exec` | Run a command synchronously, with a strict timeout (§14). |
| `exec_start` | Start a command as a background job (§15.3, §63). |
| `exec_status` | Report a job's current state and recent output (§15.3, §64). |
| `exec_output` | Retrieve a job's captured output by offset, range, or line window (§15.3). |
| `exec_cancel` | Request cancellation of a running job (§15.3). |

`docs/SPEC.md` §34.1 lists the fixed MVP tool surface and §34.2 records
what was folded into `exec`/the six future structured Git tools and why.
