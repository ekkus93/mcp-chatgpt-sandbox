# Tools

The authoritative tool contract is `schemas/tools.json`, exported from the
running server (§33.1) via `dev-workspace-mcp export-schemas`. This file is
a human-readable index alongside it — per §72, generated by hand rather
than by a script for now (no task in `docs/TODO.md` builds a generator);
if the two disagree, `schemas/tools.json` is right and this file is stale.
CI (`.github/workflows/ci.yml`) fails if a tool this file lists diverges
from `schemas/tools.json`'s own tool names, so "stale" here means "not yet
regenerated locally," not "silently drifted since the last release."

Current tool surface — `docs/SPEC.md` §34.1 lists the fixed MVP set this
implements in full; Post-MVP Operations adds explicitly versioned operator
tools beyond that original set (22 tools total as of O3):

## Repositories

| Tool | Purpose |
| --- | --- |
| `repository_list` | List repositories available to the MCP client (§7). |

## Filesystem (§13)

| Tool | Purpose |
| --- | --- |
| `list_files` | List files and directories (§13.1). |
| `read_file` | Read a repository file (§13.2). |
| `write_file` | Write complete file contents (§13.3). |
| `patch_file` | Apply a unified diff to a file (§13.4). |
| `delete_file` | Delete a repository file or directory (§13.5). |
| `search_files` | Search file names and contents (§13.7). |

## Workspace and server state

| Tool | Purpose |
| --- | --- |
| `workspace_open` | Open (creating and starting as needed) a repository's workspace (§8.3). |
| `workspace_info` | Report current workspace state (§25). |
| `server_info` | Server version, capabilities, and health (§25). |

## Operations

| Tool | Purpose |
| --- | --- |
| `resource_inventory` | Bounded, read-only inventory of MCP-owned operational resources, cleanup debt, and degraded/unavailable observations (PMOR-001..003). Optional repository/workspace filters are opaque IDs only; no host path filter is accepted. |

## Execution (§14, §15.3)

| Tool | Purpose |
| --- | --- |
| `exec` | Run a command synchronously in a workspace (§14). |
| `exec_start` | Start a command as a background job (§15.3, §63). |
| `exec_status` | Report a job's current state and recent output (§15.3, §64). |
| `exec_output` | Retrieve a job's captured output by offset, range, or line window (§15.3). |
| `exec_cancel` | Request cancellation of a running job (§15.3). |

## Structured Git (§17, §20)

Host-side reads (§20.1) and in-container mutating operations, run through
the same execution service `exec` uses.

| Tool | Purpose |
| --- | --- |
| `git_status` | Structured repository status: branch, head, ahead/behind, staged/unstaged/untracked (§17.2). |
| `git_diff` | Working-tree, staged, or commit-to-commit diff; path-filtered, stat-only mode, byte-range pagination (§17.3). |
| `git_log` | Bounded commit history (§17.3). |
| `git_commit` | Create a commit from explicit paths, with branch/HEAD guards and policy checks (§17.4, §20.6, §45, §18.9). |
| `git_pull` | Fetch then integrate from a validated remote, per `git_policy.pull_strategy` (§20.5, §18.8). |
| `git_push` | Push to a validated remote with a daemon-constructed refspec — never a client-supplied one (§20.3, §20.5, §18.9). |

`schemas/tools.json`'s own `contract_version` field is the authoritative
current value (bumped per §33.2's rules whenever the tool surface or an
output shape changes; see `src/dev_workspace_mcp/schema_export.py`'s own
change-comment history for what each bump was) — not repeated here, so
this file does not itself go stale on every patch bump the way an inlined
number would.
